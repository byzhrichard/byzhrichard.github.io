概述

  • 应用层 = 信的内容
  • 传输层 = 挂号信:不丢不乱
  • 网络层 = 规划城市之间的路线
  • 数据链路层 = 每一段路上的交接
  • 物理层 = 真正跑在路上的卡车

internet: 泛指互联网 Internet: 专指全球最大的互联网(使用TCP/IP)

边缘部分: 主机(手机/电脑/服务器, 客户使用) 核心部分: 网络+路由器 -> 为边缘提供连通和交换服务

边缘部分的两种通信方式:

  • 客户-服务器 C/S (client/server)
  • 对等方式 P2P (peer to peer) [e.g. BT下载]

不用 电路交换 和 报文交换, 而是 分组交换

  • 不独占线路; 分组小, 时延短
  • 每个分组都要带首部; 要在路由器里排队

计算机网络的分类:

网络速率:

带宽: (bit/s)

吞吐量: 是实际的带宽, 往往比带宽小

时延:

  • 发送时延: 把一个分组的所有byte推上链路所需的时间 发送时延 = 数据长度(bit) / 发送速率(bit/s)

    • 提高带宽只能减少发送时延

  • 传播时延: 电磁波在信道里跑完这段距离的时间 传播时延 = 信道长度(m) / 传播速率(m/s)

    • 传播时延只和距离和介质有关, 光纤中约5us/km=2x10^8^m/s

  • 处理时延

  • 排队时延

总时延=发送+传播+处理+排队

时延带宽积: 链路上正在传输的bit数, 也就是管道的容积 时延带宽积 = 传播时延 x 带宽

往返时间 RTT:

信道利用率: (信道利用率越高, 排队时延越大)

当前排队时延D = 空闲时排队时延D0 / (1-利用率U)

协议: 同一层的通信双方要遵守的规则(协议是水平的, 对等层之间的规则)

  • OSI七层参考模型 -> 理论完整, 但过于复杂
  • TCP/IP (网络接口层/网际层/传输层/应用层) -> great

教学上分五层: 物理层/网络接口层/网际层/传输层/应用层

  • 应用层: 直接为应用进程服务 e.g. HTTP, DNS, SMTP
  • 传输层: 进程 <-> 进程 (端到端) e.g. TCP, UDP
  • 网络层: 主机 <-> 主机 (跨越多个路由器) e.g. IP, 路由选择
  • 数据链路层: 在一段链路上, 以帧为单位传输数据 e.g. PPP, 以太网
  • 物理层: 在介质上透明的传输比特流 e.g. 电压, 光, 电磁波

每一层传输的数据单元都有专属的名字

  • 应用层: 报文message
  • 传输层: 报文段segment / 用户数据报
  • 网络层: IP数据报 / 分组package
  • 数据链路层: 帧frame
  • 物理层: 比特bit

封装与解封装:

中间设备分别实现到了哪一层:

TCP/IP体系是沙漏形的:

  • 可以有各种应用和网络, 但中间网络层都经过IP这一个协议
  • 网络层向上只提供无连接, 可靠性交给端系统的TCP来保证

物理层

传输介质:

  • 导引型
    • 双绞线
    • 同轴电缆: 带宽大, 损耗小, 抗干扰
      • 多模光纤
      • 单模光纤
    • 光线
  • 非导引型
    • 无线电/微波/红外

通信方式:

  • 单工 (e.g. 广播电台)
  • 半双工: 不能同时 (e.g. 对讲机)
  • 全双工: 可以同时 (e.g. 打电话)

码元: 一个固定时长的信号波形, 代表一个离散的数值

波特率: 每秒传多少个码元 (如果码元有V种状态, 那么码元就能携带 $\log_2(V)$ 个比特)

比特率: 每秒传多少个比特 比特率 = 波特率 * log2(V)

奈奎斯特定理: 在理想信道中, 极限码元传输速率是2W波特 (W: 信道带宽, 单位Hz) 极限数据率 = 2W * log2(V)

-> 增大V来让每个码元携带更多比特, 可提高极限数据率

香农定理: 在有噪声的信道中, 极限数据率 = W * log2(1+S/N), 其中信噪比 用比值表示 (S/N: 信噪比, 有分贝表示[dB]和比值表示[单位1]) (分贝表示=10*log10(比值表示))

-> 给出的是绝对上限, 再怎么编码V也超不过上限

两个定理的数据同时给出时, 最大数据率取二者中较小的那个

数字信号编码:

  • 不归零编码NRZ (高电平表示1, 低电平表示0) -> 但连续出现很多1或0时, 接收方无法提取时钟
  • 曼彻斯特编码 (在每一位的中间都有一次跳变, 中间向下跳表示1, 中间向上跳表示0) -> 跳变本身就可以当时钟用 -> 传统以太网的选择
  • 差分曼彻斯特编码 (在每一位的中间都有一次跳变, 但只用来同步; 开始的边界有跳变表示0, 开始的边界无跳变表示1)

曼彻斯特编码每个比特bit要用两个码元, 所以比特率=码元速率/2, 编码效率只有50%

数字信号->模拟信号编码:

  • 调幅ASK: 用不同的振幅表示0和1
  • 调频FSK: 用不同的频率表示0和1
  • 调相PSK: 用不同的相位表示0和1

正交振幅调制QAM: 把振幅和相位结合起来 (e.g. 16-QAM的一个码元携带4比特)

物理层设备:

  • 中继器: 整形, 放大, 延长距离
  • 集线器: 多端口的中继器 (只认识比特, 不认识帧)

数据链路层 / 成帧与差错检测

链路: 点到点的物理线路 数据链路: 链路+实现通信协议的硬件和软件

数据链路层传输的数据单元叫 帧 frame

MTU: 最大传送单元 (帧的数据部分的长度上限)

三个基本问题:

  • 封装成帧: 在数据前后加首部SOH和尾部EOT
  • 透明传输: 在控制字符前面插入一个转义字符ESC
  • 差错检测

零比特填充:

  • 发送方在数据中每遇到连续五个1, 就在后面插入一个0
  • 接收方在数据中每遇到连续五个1, 就删掉后面的一个0

-> 数据中永远不会出现六个连续的1

帧定界符: 7E: 0111 1110

差错检测:

  • 奇偶校验: 加一位使1的个数为奇数或偶数
  • 循环冗余检验CRC: 事先约定一个多项式P, 经过处理后生成FCS附在数据后面一起发过去

例题: 数据101001, 约定P(x)=x^3^+x^2^+1即1101

  • 补3个0 -> 101001000
  • 最高位对齐除以(异或)1101 -> 011101000
  • 次高位对齐除以(异或)1101 -> 000111000
  • 次次高位对齐除以(异或)1101 -> 000001100
  • 次次次高位对齐除以(异或)1101 -> 000000001
  • 余数为001, 所以发送101001001
  • 接收方把接收到的101001001除以1101
    • 余数为000, 说明数据没错, 接收
    • 余数非000, 说明数据出错, 丢弃

纠错: 海明码

-> 但是4位数据需要3位纠错位, 代价太高

-> 网络中, 只检错, 不纠错, 如果出错就重传

点对点协议PPP:

可靠传输与滑动窗口

出错的帧被丢弃了怎么办 -> 自动重传请求ARQ (确认+重传):

  • 停止等待协议

    • 流水线传输与滑动窗口

  • 后退N帧协议GBN

  • 选择重传SR

停止等待协议:

  • 丢帧

    • 发一帧, 等接收方的确认ACK再发下一帧
    • 如果超时计时器到期, 就重传

  • 丢确认

    • 如果接收方的确认ACK被丢弃, 接收方就会收到重复的帧
    • 接收方发现是重复帧, 就丢掉, 再发一次上次的确认ACK

停止等待协议的信道利用率U太低:

-> 大部分时间, 信道都在空等

流水线传输与滑动窗口:

  • 落在发送窗口内的帧可以连续发出
  • 收到确认后, 窗口向前滑动

后退N帧协议GBN:

  • 接收方按顺序接收, 采用累计确认
  • ACK2表示二号及以前的帧都收到了
  • 如果丢帧, 则后面传来的帧也都丢弃, 发送方超时后, 从丢失的那一帧重传(也就是后退N帧)

用 n 位给帧编号, GBN的发送窗口最大是 2^n^-1

选择重传SR:

  • 接收窗口>1
  • 丢帧后先缓存正确到达的帧, 发送方只重传丢失的那一帧
  • 需要满足: 发送窗口+接收窗口<=2^n^ (一般都是: 发送窗口=接收窗口=2^n-1^)

三种协议的对比:

信道利用率U = (一个周期内发出的帧数 * TD) / 周期

介质访问控制MAC

点对点链路很简单, 但是! 局域网里, 常常是多台主机共享同一条广播信道, 如果两台主机同时发送, 信道就会叠加, 发生碰撞 -> MAC解决who以及when能发

  • 信道划分: 复用
    • 频分复用FDM: 把频带分成多个子频带, 每个用户一个子频带
    • 时分复用TDM: 把时间分成一帧帧, 每个用户固定一个时隙
    • 波分复用WDM: 光的频分复用
  • 随机访问
  • 轮询访问

为了解决TDM的时隙浪费, STDM按需动态分配, 时隙不再空着

码分多址CDMA:

  • 每个站分配一个唯一的M位码片序列
    • 发1 <-> 发送码片序列
    • 发0 <-> 发送码片序列的反码
  • 各站的码片序列两两正交, 即规格化内积为0 [S*T=(1/m)ΣSiTi=0]
  • 所有站可以在同一时间, 同一频带发送
  • 接收方想知道某个站(A/B/C/D)发了什么: 用该站的码片序列A/B/C/D和收到的叠加信号S求规格化内积
    • 内积为1 -> 发的是1
    • 内积为-1 -> 发的是0
    • 内积为0 -> 未发送

随机访问: 所有站都可以随时发送, 冲突了再想办法

  • 最早的是ALOHA协议: 想发就发
  • 改进后的是CSMA协议: 先听信道, 空闲才发
  • 传统以太网用的是CSMA/CD协议: 先听后发, 边发边听, 冲突停发, 随机重发

但是还会碰撞, 根据下图, 所以争用期为2τ

-> 帧不能太短, 最短帧长 = 2τ * 数据率

碰撞后用截断二进制指数退避:

无线局域网用CSMA/CA: [不是CSMA/CD]

  • 定义一个帧间间隔DIFS
  • 定义一个短帧间间隔SIFS
  • 还可以用RTS请求发送, CTS允许发送

轮询访问: e.g. 令牌环

以太网与交换机

以太网:

每块网卡都有一个MAC地址, 也叫硬件地址或物理地址

  • 长48位, 通常写成6组十六进制, 即6B
  • 前24位是厂商代码, 后24位由厂商自行分配
  • 全1的地址, 是广播地址: FF FF FF FF FF FF

以太网V2帧格式:

  • 目的地址: 网卡一收到前6个字节就能判断是不是发给自己的
  • 类型: 指明上层协议, 比如0x0800代表IP
  • FCS: 帧检验序列
  • 以太网最短帧64字节, 故数据若不足46字节需要填充到46字节
  • 数据部分最多1500字节

后来集线器被以太网交换机取代:

  • 本质是多端口网桥, 工作在数据链路层
  • 能看懂帧里的MAC地址, 把帧转发到目的主机所在的端口
  • 多对主机可以同时通信, 全双工时不会碰撞

交换机的自学习: 学习主机在哪个端口

  • 一开始交换表是空的
  • A发帧给交换机, 交换机得到了A的端口是1
  • 但还不知道B的端口, 所以把帧给所有其他主机都发一遍, 叫做泛洪
  • B回复A时, 交换机得到了B的端口是2
  • 以后A和B通信, 就可以直接定向转发
  • 交换表的每个表项都有有效时间, 过期就自动删除

冲突域和广播域:

虚拟局域网VLAN:

  • 把一条交换机上的主机按需分成几个局域网
  • 每个VLAN是一个独立的广播域
  • VLAN帧: 在以太网里插入一个4字节的标记, 其中VID有12位是VLAN号

以太网的发展:

  • 从 10Mbit/s 到 100Mbit/s 到 1Gbit/s 到 10Gbit/s
  • 帧格式始终不变
  • 告诉以太网一般在全双工方式下工作, 不再需要CSMA/CD

无限局域网802.11, 也就是WIFI:

  • 主机通过接入点AP通信
  • 帧首部通过四个地址字段
    • 地址1: AP: 这一跳的接收方
    • 地址2: A: 这一跳的发送方
    • 地址3: R: 另一端的源地址或目的地址
    • 地址4: 不常用

网络层与IP数据报

虚电路 vs 数据报: 互联网选择了数据报, 把可靠性交给端系统去解决

转发: 路由器查转发表, 把数据从合适的端口转发出去 [本地的]

路由选择: 许多路由器算出最佳路径, 生成路由表 [全网范围的]

软件定义网络SDN: (控制与转发分离)

  • SDN控制器: 计算路由, 下发流表
  • 路由器只负责按流表转发

IPv4数据报首部:

  • 版本: 4 bit
  • 首部长度: 4 bit, 单位是 x4字节
  • 总长度: 16 bit, 单位是 x1字节 [-> 一个IP数据报最长 2^16^-1=65535 字节]
  • 标识, 标志, 片偏移: 用于分片
  • 片偏移: 单位是 x8字节
  • 生存时间TTL: 每经过一个路由器就-1, 到0就丢弃, 放置兜圈子
  • 协议: 数据交给谁
    • 6是TCP
    • 17是UDP

这三个字段是不同的单位:

  • 首部长度5代表20字节, 首部长度15代表60字节

IP分片:

  • 当数据报比MTU还大时, 就要分成几片
  • 每一片都有自己的首部
  • 标识相同
  • 标志里, MF=1表示后面还有分片, DF=1表示不允许分片
  • 片偏移表示这一片在原数据中的位置 (除以8) 片偏移 = 该片数据起始字节 / 8
  • 除最后一片外, 每片数据长度都是 8 的整数倍

分片在源主机或路由器上进行, 重组只在目的主机上进行

IP地址与子网划分

IP地址:

  • 是分配给互联网上每台主机每个路由器的每一个接口的32位标识符
  • 通常写成点分十进制, 如192.168.1.10
  • 分为网络号和主机号

192: 1100 0000 168: 1010 1000 1: 0000 0001 10: 0000 1010

分类的IP地址:

特殊的IP地址:

  • 主机号全0 [192.168.1.0] -> 表示网络本身
  • 主机号全1 [192.168.1.255] -> 表示网络的广播地址
  • 127开头 [127.0.0.1] -> 环回地址, 用于本机测试
  • 私有地址: 只能在内网使用
    • 10.0.0.0 ~ 10.255.255.255
    • 172.16.0.0 ~ 172.31.255.255
    • 192.168.0.0 ~ 192.168.255.255

子网划分与子网掩码:

  • 从主机号里借几位作为子网号
  • 子网掩码: 网络号和子网号对应的位都是1, 主机号对应的位都是0
  • IP地址与掩码逐位相与, 就得到网络地址
    • 网络号和子网号与1后还是本身
    • 主机号与0后就是全0, 表示网络本身 -> 得到网络地址

无分类编址CIDR: [不再区分ABC类]

  • 网络前缀: 网络号与子网号的长度
  • 直接用"斜线记法"写出网络前缀的长度 e.g. 192.168.1.0/24的网络前缀长度24位
  • 前缀相同的连续地址组成一个CIDR地址块

例题: 把 192.168.10.0/24 平均分成4个子网

  • 第四个字节需要借出2位作为子网号 -> /26
  • 掩码变成 255.255.255.192
  • 每个子网有 2^6^=64 个地址, 有 2^6^-2=62 台主机

路由聚合(构成超网): 把多个前缀相同的小地址块合成一个大地址块, 在路由表里只占一项

  • 但是一个地址可能同时匹配路由表里的好几项
  • 这时要选前缀最长的那一项 -> 最长前缀匹配
  • 因为前缀越长, 地址块就越小, 路由就越具体

例题: 路由表的最长前缀匹配

目的网络 192.168.10.5:

  • 能匹配第一项, 因为前16位都一样
  • 能匹配第二项, 因为前24位都一样
  • 能匹配第三项, 前缀长度是0, 任何 IP 都和它匹配

-> 优先选 接口2

目的网络 10.1.1.1:

  • 不匹配第一项
  • 不匹配第二项
  • 能匹配第三项, 前缀长度是0, 任何 IP 都和它匹配

-> 优先选 接口3
